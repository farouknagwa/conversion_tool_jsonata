JSON CONVERSION TOOL - JSONATA VERSION

REQUIREMENTS:
pip install -r requirements.txt
(Requires: jsonata-python, tqdm, openpyxl, beautifulsoup4)

BASIC USAGE:
python3 -B main.py                                    # Convert all files in INPUT/ folder
python3 -B main.py -v                                 # Verbose mode with detailed progress
python3 -B main.py --input path/to/files              # Specify custom input path
python3 -B main.py --output path/to/output            # Specify custom output path
python3 -B main.py --types mcq,mrq,counting           # Filter by question types
python3 -B main.py --dry-run                          # Validation only, no files written

WORKFLOW USAGE (Step4_OUTPUT -> Step5_OUTPUT):
Use this mode when your dataset is already arranged in the Step4 pipeline structure:
- Step4_OUTPUT/<QuestionId>/Updated/<QuestionId>.json is the JSON that must be cleaned + converted in place.
- Step4_OUTPUT/questions_updated_sheet.csv exists and must be rewritten to one row per QuestionId.

python3 -B workflow_main.py                                               # Uses Step4_OUTPUT -> Step5_OUTPUT
python3 -B workflow_main.py -v                                            # Verbose workflow logging
python3 -B workflow_main.py --inputstep path/to/Step4_OUTPUT --outputstep path/to/Step5_OUTPUT

WORKFLOW OUTPUTS (Step5_OUTPUT):
- Step5_OUTPUT is first emptied, then fully copied from Step4_OUTPUT (excluding *.log files).
- Only QuestionId rows with IsSuccess=True are processed in Step5; IsSuccess=False rows are skipped and their JSONs are not modified.
- Step5_OUTPUT/questions_updated_sheet.csv is rewritten to these columns (one row per QuestionId):
  QuestionId, SectionCode, language_iso_code, subject_id, subject_name, grade_id,
  grade_url_text, country_iso_code, parent_id, IsSuccess, Error Message, Error Type, Warning Message
- A Step5 log file is created in Step5_OUTPUT root:
  Step5_JsonCleaningAndConversion_<YYYYMMDD>_<HHMMSSmmm>.log
- No OUTPUTS/CONVERTED or failure folders are created in workflow mode; JSONs are edited in place inside Step5_OUTPUT.

INPUT/OUTPUT:
- Place JSON files in INPUT/ folder (supports subdirectories)
- Converted files saved to OUTPUTS/CONVERTED/
- Failed files saved to:
  * PRE_CONVERSION_VALIDATION_FAILED/ (original files with blocking errors)
  * CONVERSION_FAILED/ (original files)
  * POST_CONVERSION_VALIDATION_FAILED/ (converted files)
- Error reports in LOGS_REPORTS/:
  * .xlsx with two sheets: "Errors" (blocking) and "Warnings" (non-blocking)
  * .log with detailed error and warning information

WARNINGS vs ERRORS:
- ERRORS: Block conversion, file moves to failure folder
- WARNINGS: Non-blocking issues, conversion proceeds normally
  * Examples: multipart without statement, single-part answer HTML structure
  * Tracked separately in Excel "Warnings" sheet
  * Visible in console summary as "Total warnings: N"

SUPPORTED QUESTION TYPES:
mcq, mrq, gmrq, frq, frq_ai, oq, gapText, string, opinion, matching, counting, puzzle, input_box

CONVERSION RULES:
JSONata transformation rules located in JSONATA_RULES/ folder (one .jsonata file per type)

OUTPUT STRUCTURE:
- Root fields: question_id, parent_id, language_code, language, country_code, country, 
  subject, subject_id, grade, grade_id, number_of_parts, section_id, source, content
- content.parts: Array of converted parts (one per question part)
- content.statement: Required for multipart questions only
- Each part includes: n (part number), type, stem, type-specific fields, explanation (optional)

DOCUMENTATION:
- See individual type structure files (mcq.txt, mrq.txt, etc.) for detailed JSON structure
- See pre-conversion-validations.txt for input validation rules
- See post-conversion-validations.txt for output validation rules
